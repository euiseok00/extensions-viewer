# 02. 요구사항

> 역할: 만들어야 할 기능과 품질 기준을 수용 기준과 함께 정의한다.

## 기능 요구사항

기능 6개가 MVP의 전부이며, 각각 수용 기준을 만족해야 완료로 본다.

| ID | 기능 | 수용 기준 |
|---|---|---|
| F1 | `/extensions-viewer` 명령 | 실행 시 URL 한 줄을 출력한다. 서버가 이미 떠 있으면 재사용한다. Claude가 자동 호출하지 못한다(`disable-model-invocation: true`). |
| F2 | 플러그인 목록 | 이름, 버전, 범위(user/project/local), 활성 여부를 표시한다. `claude plugin list --json`을 우선 쓰고, 실패하면 `settings.json`의 `enabledPlugins`로 대체한다. |
| F3 | MCP 목록 | 이름, 출처(`.mcp.json`, `~/.claude.json`, 플러그인), 전송 방식(stdio/http), 실행 명령, 설정상 활성 여부를 표시하고 비밀값은 가린다. |
| F4 | 스킬 목록 | 이름, 설명, 위치(사용자/프로젝트/플러그인)를 표시한다. `~/.claude/skills`, `.claude/skills`, 플러그인 폴더를 스캔하고 `SKILL.md` 상단 메타데이터를 읽는다. |
| F5 | 화면 | 탭 3개, 검색, 탭별 개수, "설정 파일 기준" 라벨을 보여준다. |
| F6 | 오류 처리 | 수집기 하나가 실패해도 나머지는 표시하고, 실패 사유를 해당 탭에 보여준다. |

## 단계 5 기능 요구사항 (UI 개선)

MVP(F1~F6) 이후 추가한다. 화면 구성과 상호작용은 `07-ui-design.md`에 있다.

| ID | 기능 | 수용 기준 |
|---|---|---|
| F7 | 포함관계 | 플러그인 유래 스킬·MCP는 `parent`(플러그인 id)를 가진다. 플러그인 행을 펼치면 하위 스킬·MCP가 보이고, 스킬·MCP 행에는 소속 플러그인 칩이 보인다. 칩을 누르면 그 플러그인으로 필터된다. 플러그인 행에 하위 개수(스킬 N · MCP N)를 표시한다. 플러그인이 비활성이면 하위 항목에 "플러그인 비활성" 표시를 붙인다(효과는 단정하지 않는다). |
| F8 | 필터 | 범위(user/project/local/plugin), 활성 상태(활성/비활성/알 수 없음), 출처 플러그인, 텍스트 검색(이름·설명·명령)을 조합할 수 있다. 같은 그룹 안은 OR, 그룹 사이는 AND다. "N개 중 M개 표시"와 필터 초기화를 제공하고, 상태는 URL 해시에 유지된다. |
| F9 | 보기 모드 | 트리(플러그인 기준 그룹)와 평면 목록을 전환한다. 이름·범위로 정렬할 수 있다. |
| F10 | 상세 패널 | 행을 선택하면 마스킹된 detail 전체와 source 경로를 보여주고, 경로를 복사할 수 있다. 같은 이름이 여러 곳에 있으면 "같은 이름 N곳"을 표시한다(어느 쪽이 적용되는지는 단정하지 않는다). |
| F11 | 상태·접근성 | 로딩, 빈 결과, 수집 실패, 서버 종료 상태를 구분해 보여준다. 키보드만으로 검색(`/`), 행 이동, 상세 열기·닫기가 가능하다. 범위·상태는 색 외에 글자나 모양으로도 구분한다. 라이트·다크 테마를 따른다. 새로고침 버튼으로 설정을 다시 읽는다. |

제약: `innerHTML` 금지, 외부 리소스 0건, 읽기 전용 유지는 그대로다.

## 비기능 요구사항

수치는 측정 전의 목표값이다.

| 항목 | 목표 |
|---|---|
| 의존성 | 런타임 외부 패키지 0개 |
| 성능 | 첫 응답 2초 이내(CLI 호출 포함) |
| 상주 시간 | 유휴 10분 후 자동 종료 |
| 호환성 | macOS, Linux, Windows / Node.js 22 이상 |
| 신뢰성 | 수집기 하나의 실패가 전체를 막지 않는다 |
| 유지보수 | 수집기 인터페이스 통일, 내장 `node:test`로 단위 테스트 |

보안 요구사항은 `04-security.md`에서 따로 다룬다.
