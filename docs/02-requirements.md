# 02. 요구사항

> 역할: 만들어야 할 기능과 품질 기준을 수용 기준과 함께 정의한다.

## 기능 요구사항

기능 6개가 MVP의 전부이며, 각각 수용 기준을 만족해야 완료로 본다.

| ID | 기능 | 수용 기준 |
|---|---|---|
| F1 | `/extensions-viewer` 명령 | 실행 시 URL 한 줄을 출력한다. 서버가 이미 떠 있으면 재사용한다. Claude가 자동 호출하지 못한다(`disable-model-invocation: true`). |
| F2 | 플러그인 목록 | 이름, 버전, 범위(user/project/local), 활성 여부를 표시한다. `claude plugin list --json`을 우선 쓰고, 실패하면 `settings.json`의 `enabledPlugins`로 대체한다. |
| F3 | MCP 목록 | 이름, 출처(`.mcp.json`, `~/.claude.json`, 플러그인), 전송 방식(stdio/http), 실행 명령, 설정상 활성 여부를 표시하고 비밀값은 가린다. |
| F4 | 스킬 목록 | 이름, 설명, 위치(사용자/프로젝트/플러그인)를 표시한다. `~/.claude/skills`, `.claude/skills`, 플러그인 폴더를 스캔하고 `SKILL.md` 상단 메타데이터를 읽는다. |
| F5 | 화면 | 탭 3개, 검색, 탭별 개수, "설정 파일 기준" 라벨을 보여준다. |
| F6 | 오류 처리 | 수집기 하나가 실패해도 나머지는 표시하고, 실패 사유를 해당 탭에 보여준다. |

## 비기능 요구사항

수치는 측정 전의 목표값이다.

| 항목 | 목표 |
|---|---|
| 의존성 | 런타임 외부 패키지 0개 |
| 성능 | 첫 응답 2초 이내(CLI 호출 포함) |
| 상주 시간 | 유휴 10분 후 자동 종료 |
| 호환성 | macOS, Linux, Windows / Node.js 20 이상(확정 전) |
| 신뢰성 | 수집기 하나의 실패가 전체를 막지 않는다 |
| 유지보수 | 수집기 인터페이스 통일, 내장 `node:test`로 단위 테스트 |

보안 요구사항은 `04-security.md`에서 따로 다룬다.
