# 07. UI·인터랙션 설계

> 역할: 단계 5(UI 개선)의 화면 구성, 상호작용, 시각 규칙을 정의한다. 기능의 수용 기준은 `02-requirements.md`의 F7~F11이다.

## 설계 원칙

1. **포함관계가 먼저 보인다.** 스킬·MCP가 어느 플러그인에서 왔는지가 한눈에 읽혀야 한다.
2. **필터는 상태가 보인다.** 지금 무엇이 걸러졌는지, 몇 개가 남았는지를 항상 표시한다.
3. **색에만 의존하지 않는다.** 범위·상태는 색과 함께 글자 또는 모양으로 구분한다.
4. **보안 제약을 유지한다.** `textContent`만 쓰고, CSP `default-src 'self'` 아래에서 외부 폰트·CDN·인라인 스크립트를 쓰지 않는다.

## 화면 구성

```text
┌──────────────────────────────────────────────────────────────┐
│ extensions-viewer            설정 파일 기준 · 새로고침 ⟳       │
├──────────────────────────────────────────────────────────────┤
│ [플러그인 2] [MCP 3] [스킬 29]        ( 검색  /            )   │
├──────────────────────────────────────────────────────────────┤
│ 범위 ▢user ▢project ▢local ▢plugin   상태 ▢활성 ▢비활성 ▢알 수 없음 │
│ 출처 [전체 ▾]     보기 (●트리 ○목록)  정렬 [이름 ▾]   필터 초기화 │
│ 29개 중 12개 표시                                              │
├───────────────────────────────────────┬──────────────────────┤
│ ▾ caveman@caveman   user · 활성       │ 상세                  │
│     스킬 17 · MCP 0                    │ 이름 caveman          │
│   ├ skill  caveman          plugin    │ 범위 plugin           │
│   ├ skill  caveman-commit   plugin    │ 출처 C:\...\SKILL.md ⧉│
│   └ …                                 │ 설명 …                │
│ ▸ ponytail@ponytail user · 활성        │ 같은 이름 2곳 ▸       │
│ ● mcp  srv   user  stdio              │                       │
└───────────────────────────────────────┴──────────────────────┘
```

- 상단 탭은 종류, 그 아래 필터 줄은 범위·상태·출처를 다룬다. 둘은 AND로 조합된다.
- 플러그인 탭에서 행을 펼치면 하위 스킬·MCP가 나온다. 스킬·MCP 탭에서는 각 행에 소속 플러그인 칩이 붙는다.
- 오른쪽 상세 패널은 행을 선택했을 때만 열린다. 좁은 화면(폭 700px 미만)에서는 행 아래로 펼쳐진다.

## 상호작용

| 동작 | 결과 |
|---|---|
| 행 클릭 | 상세 패널 열기. 같은 행 재클릭 또는 `Esc`로 닫기 |
| 플러그인 행의 ▸/▾ | 하위 스킬·MCP 접기·펼치기. 기본은 접힘 |
| 소속 플러그인 칩 클릭 | 출처 필터를 그 플러그인으로 설정하고 플러그인 행을 강조 |
| 범위·상태 칩 클릭 | 해당 값으로 필터 토글. 여러 개 선택 가능(같은 그룹은 OR) |
| `/` | 검색창 포커스 |
| `↑` `↓` `Enter` | 행 이동, 상세 열기 |
| 필터 초기화 | 모든 필터와 검색어를 비움 |
| 새로고침 | `/api/extensions`를 다시 불러옴(설정 파일을 다시 읽음) |
| 경로 복사 | 상세 패널의 source를 클립보드에 복사하고 "복사됨"을 잠깐 표시 |

필터·보기·정렬 상태는 URL 해시(`#scope=user,plugin&q=cave`)에 담아 새로고침해도 유지한다. 해시는 서버로 전송되지 않으므로 토큰과 무관하다.

## 상태별 화면

| 상태 | 표시 |
|---|---|
| 로딩 | 탭 영역에 "불러오는 중" 문구(스피너 없이 텍스트) |
| 빈 결과(필터 때문) | "조건에 맞는 항목이 없습니다" + 필터 초기화 버튼 |
| 빈 결과(원래 없음) | "설정에서 찾은 항목이 없습니다" + 읽은 위치 목록 |
| 수집 실패 | 해당 탭 상단에 오류 배너, 나머지 탭은 정상 표시(F6) |
| 서버 종료됨 | "서버가 종료되었습니다. `/extensions-viewer`를 다시 실행하세요" |

## 시각 규칙

- **색 토큰**: CSS 변수로 정의하고 `prefers-color-scheme`로 라이트·다크를 전환한다. 대비는 본문 기준 4.5:1 이상을 목표로 한다(측정 전 목표값).
- **범위 칩**: user, project, local, plugin을 각각 다른 색 + 글자로 표시한다. 색만으로 구분하지 않는다.
- **상태 표시**: 활성은 ● 채움, 비활성은 ○ 비움, 알 수 없음은 점선 + "?" 로 모양을 달리한다.
- **종류 아이콘**: 외부 아이콘 폰트 없이 유니코드 기호 또는 CSS로 그린 모양을 쓴다.
- **검색어 강조**: `<mark>` 요소를 `createElement`로 만들어 일치 부분만 감싼다. 문자열 HTML 조립은 하지 않는다.
- **긴 값**: 경로·명령은 한 줄 말줄임 + 상세 패널에서 전체 표시한다.
- **밀도**: 행 높이를 고정해 29개 이상에서도 스캔하기 쉽게 한다. 가상 스크롤은 항목이 수백 개를 넘기 전에는 쓰지 않는다.

## 구현 영향

- **데이터**: 수집기가 플러그인 유래 스킬·MCP에 `parent`(플러그인 id)를 채운다. API는 평면 목록을 유지하고 트리는 화면에서 만든다. (`03-architecture.md` 데이터 모델)
- **파일**: 필터·트리 계산은 순수 함수 모듈로 분리해 `node:test`로 검증한다. 서버의 정적 파일 허용 목록에 추가한다.
- **하지 않는 것**: 항목 편집·ON/OFF 저장(읽기 전용 유지), 외부 라이브러리, 서버 측 필터링.

## 미확인

- 동명 스킬이 여러 범위에 있을 때 실제 우선순위는 확인하지 못했다. 화면은 "같은 이름 N곳"만 보여주고 어느 쪽이 적용되는지는 단정하지 않는다.
- 플러그인이 비활성일 때 하위 스킬·MCP가 실제로 로드되지 않는지는 확인하지 못했다. 화면은 "플러그인이 비활성"이라는 사실만 표시하고 효과는 단정하지 않는다.
- 플러그인은 스킬·MCP 외에 명령, 에이전트, 훅도 포함할 수 있으나 이 도구의 범위(3종) 밖이다.
