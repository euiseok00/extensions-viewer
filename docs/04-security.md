# 04. 보안 설계

> 역할: 이 도구가 내부 정보 유출 경로가 되지 않도록 위협별 대응과 검증 방법을 정의한다.

## 왜 읽기 전용에서도 보안이 중요한가

MCP 설정에는 API 키가 들어 있는 경우가 많다. 로컬 서버가 이를 그대로 보여주면 같은 PC의 다른 프로그램이나 악성 웹페이지가 읽어 갈 수 있다.
설정을 바꾸지 않아 쓰기 위협은 없지만, **읽기 유출**은 그대로 남는다.

## 위협별 대응

| 위협 | 대응 |
|---|---|
| 외부 접속 | `127.0.0.1`에만 바인딩, 랜덤 포트 |
| 무단 접근 | 실행마다 랜덤 토큰(32바이트), 상수 시간 비교, 없거나 틀리면 403 |
| DNS 리바인딩 | Host 헤더가 `127.0.0.1:포트` 또는 `localhost:포트`가 아니면 403 |
| 크로스 사이트 읽기 | CORS 헤더 미설정, CSP `default-src 'self'` |
| XSS | 플러그인·스킬의 이름·설명은 신뢰 불가 데이터라 `textContent`만 사용, `innerHTML` 금지 |
| 비밀값 유출 | MCP `env`·`headers` 값과 토큰형 `args`를 마스킹, 키 이름만 표시 |
| 토큰 노출 | 로그·오류 메시지에 출력 금지, 첫 접속 후 쿠키(HttpOnly, SameSite=Strict)로 교체 |
| 명령 주입 | `execFile` 사용, 사용자 입력을 명령에 넣지 않음 |
| 상주 노출 | 유휴 10분 후 자동 종료, 상태 파일 권한 0600 |
| 캐시 | `Cache-Control: no-store` |

## 구현 전 확정 필요 사항

아래는 규칙이 비어 있어 구현 전에 정해야 한다. 확정 전까지 `05-roadmap.md` 미확인 표로 관리한다.

- **마스킹 범위 (단계 1에서 확정, `src/sanitize.ts`)**: `env`·`headers`는 값을 버리고 키 이름만 낸다(플러그인 `.mcp.json` 포함). `args`는 이름에 token·secret·password·api key·auth 등이 든 플래그의 다음 값, `KEY=값`, `sk-`·`ghp_`·`xox*-`·`AKIA`·`eyJ`·`Bearer ` 접두 값을 가린다. `url`과 URL 형태 `args`는 userinfo와 쿼리 값 전부를 가린다. 알려진 접두사가 없고 이름도 평범한 임의 문자열 비밀은 걸러지지 않는다.
- **상태 파일 권한**: 0600은 Windows에서 적용되지 않는다. 단계 4에서 사용자 프로필 하위 폴더의 상속 ACL에 의존하기로 하고 검증 항목을 플랫폼별로 나눴다. 공용 계정 환경은 고려하지 않는다.
- **서버 재사용 판별**: 런처는 pid를 믿지 않는다. 상태 파일의 포트에 토큰으로 접속해 302가 와야 재사용하고, 아니면 상태 파일을 지우고 새로 기동한다. 강제 종료 시 상태 파일이 남을 수 있으나 이 판별이 걸러낸다.
- **CLI 호출 실패**: `execFile`에 타임아웃을 둔다. 초과하거나 실패하면 `settings.json` 기반 대체 경로로 넘어가고, 사유는 해당 탭에 표시한다(F6).

## 검증 항목 (단계 2에서 자동화)

- [x] 토큰 없이 `GET /` 요청 시 403
- [x] 잘못된 토큰으로 요청 시 403
- [x] `Host: evil.example` 헤더로 요청 시 403
- [x] 정상 토큰과 Host로 요청 시 200
- [x] 응답 JSON 어디에도 마스킹 대상 값이 남지 않음 (픽스처에 가짜 키를 넣고 검사)
- [x] 스킬 설명에 `<script>`가 있어도 실행되지 않음
- [x] 유휴 10분 후 프로세스가 종료됨
- [x] 상태 파일 권한: macOS·Linux는 0600 (테스트로 검증, CI에서 확인 예정). Windows는 모드가 적용되지 않아 사용자 프로필 하위 폴더의 상속 ACL에 의존한다. 이 PC에서 `icacls`로 SYSTEM, Administrators, 본인 계정만 접근 가능함을 확인했다.
